# ICE 运营台：围绕现有 Agent 的实施计划

日期：2026-10-23  
版本：v1.2  
状态：主体方案已获认可；已完成任务存储、版本恢复、失败响应留存与离线浏览器机制验证，代码已按独立工作树分支合入正式仓库本地 main。真实模型质量和新打包版凭据恢复尚未验收；本轮未新增收费调用。  
已确认：用户负责最终人工评审；阶段 A 根据真实资料确定分类门槛；TikHub 真实探测累计预算上限为人民币 1 元。

本版优先级：A 完成身份与最小契约后，立即交付 T 最薄闭环；B/C/D 是之后逐项加深的工作清单，不要求先完成全部诊断、接口和质量批测才能看到第一条可用结果。v1.1 原文保留在计划历史目录。

## 1. 目标与范围

以现有运营、研究、写稿和视频分析 Agent 为核心，将账号诊断、参考研究、视频改编和发布复盘连接成可保存、可继续的任务。

推荐同时支持自有账号与对标账号：自有账号决定目标、资源和评估口径，对标账号提供表达与结构参考。首版只围绕一个自有账号工作，可选择多条对标资料；多自有账号切换放到后续阶段。

主流程：账号资料与策略 → 账号诊断 → 选题与参考 → 视频分析 → 真人分镜与 AI 视频提示词 → 人工审核与发布登记 → 反馈复盘。

设计约束：数据可追溯、失败可恢复、结果可验证；保留国内/国外 → 平台 → 接口多选；新交互集中在一个任务面板，其他设置折叠，整体导航暂不重做。

- 已有账号策略及版本确认、运营建议、研究选题、参考适配、研究稿版本、发布登记与指标快照。
- 已有视频分析与改编规则 V1.1，以及采样画面、人工台词、可选外部转写、三类成果、保存参考和导出入口。
- 当前创作者分析按平台和作者名称聚合样本，尚不足以作为完整账号诊断。账号识别应使用平台与稳定账号标识；资料不足时提示身份待确认，不按同名自动认定为同一账号。
- 当前视频成果外层为 JSON，分镜和提示词主体为文本，需补逐镜结构才能进行严格验收。

## 3. 技术方案选择

推荐扩展现有工作流、存储和规则，通过一个任务面板连接各能力。优点是改动集中、兼容现有成果、便于逐段验证；需要补齐任务阶段状态和共享上下文。

独立重建通用 Agent 平台会重复现有业务能力，并扩大迁移与验证范围，本轮不采用。

## 4. P0：账号驱动的最小闭环

首个交付里程碑：一个账号 + 人工业务资料 + 本地真实视频 + 人工逐字稿 → 复用现有 Agent 生成分析、真人分镜和 AI 提示词 → 保存 → 关闭 → 重开 → 导出。

P0 不依赖真实经营表现数据，不等待实际发布或指标积累。分类门槛用隔离演示库验证，真实经营库不混入演示数据。后续真实发布与持续质量观察不阻塞该里程碑交付。

### 阶段 A：建立基线、冻结验收，并行验证接口风险

1. 使用匹配发布包的源码，记录基线；测试使用独立数据目录，保留用户现有数据。改库前先完成下述备份与回滚机制。
2. 核对现有 Agent 实际调用的规则、模型配置、输入输出和保存入口。
3. 定义一个运营任务需要的最少信息：当前账号、策略版本、任务目标、所选资料、素材与字幕来源、阶段状态、成果版本；先冻结下述账号身份契约。
4. 字段优先放入现有记录与上下文，只有不能满足关联或恢复要求时新增最少的存储结构。
5. 与契约梳理并行开展有额度上限的 TikHub 探针，先筛选零价接口是否能提供真实视频路径，再测试必要的付费接口。真实探测累计上限人民币 1 元，包含赠送额度与充值余额请求的标价，以及任何收费核验请求；账户余额是可用资金，不是执行预算。实时确认价格和计价币种，不能确认费用上限时不执行。请求前由后端事务持久预留预算，失败或超时不释放；金额使用十进制，重启不清零。界面限制不能替代后端门禁。
6. 探针记录 HTTP 与业务状态、返回字段、耗时、媒体地址是否实际可用、权限、限流和错误；输出脱敏报告与已验证接口清单。接口不可用时直接保留待接入状态，阶段 B 使用人工登记的对标资料继续。
7. 开发前固定《P0测试与评审约定-v1》中的十个主题、输入、评分表和评审人；先保存输入及规则快照，再生成结果。T 阶段先运行一个固定案例，十主题批测后续再做。账号表现/趋势门槛在 B 开发前根据资料确认，不阻塞 T 的定位、资源与创作流程。
8. 交接设为开发门槛：video_script_skill_v1.md 和 tikhub_probe.py 尚未找到。进入相应新规则/新探针开发前，须取得文件，或明确确认复用/替代方案和版本。当前已授权接口实测直接复用现有后端价格核验、鉴权和预算机制，不声称调用了未交接的探针；T 拟复用项目现有 creative-rules.txt V1.1，替代方案需在 T 开发前明确记录。

验收：现有资料可正常读取，形成改动清单、输入输出契约、固定验收样本及接口探测报告。真实探测缺少凭据时如实记录未执行，不能将文档核对或离线替身测试记为接口已验证。

#### 账号身份契约

- 所有新任务、诊断、发布记录关联本地不可变 account_uid；平台标识通过映射关联，昵称或用户可修改的账号号仅作显示别名。
- 平台身份使用平台返回的用户标识，明确保存 platform、identifier_type 和值。例如抖音 uid 与 sec_uid 分类型保存，不擅自当作同一字符串；跨类型关联需来自同份可信响应或人工确认。
- 仅有昵称时创建 identity_pending 本地账号，允许保存资料及开展本地创作；禁止按昵称自动合并账号、认领历史作品或将外部指标归为自有表现。确认平台身份或人工确认记录归属后再建立明确映射，记录确认人和依据，不将人工确认标为平台核实。
- 历史按作者名聚合的样本保留 legacy_group 身份，不自动转成平台账号。旧单账号策略及既有记录使用新增映射表关联；归属不确定的记录保留未分配，历史原字段不改写。

#### 改库前自动备份与回滚

- 任何结构迁移开始前自动创建带时间、旧结构版本和校验信息的备份；使用 SQLite 一致性备份机制，覆盖已提交的 WAL 数据，不能在运行中只复制主数据库文件。
- 验证备份可打开、完整性检查通过，且关键表和记录可读取；备份失败则禁止迁移。
- 在旧库副本中先演练迁移和回滚。迁移尽可能在事务中完成；失败不留下可继续误用的半迁移状态。
- 回滚时停止写入，保留失败后的数据库，恢复校验通过的备份，并使用对应旧版本程序验证记录和导出。保留新旧文件，不通过删除用户数据库完成恢复。
- 迁移前新增的记录不属于备份恢复点，界面明确恢复范围；不把旧备份恢复成“无损合并新数据”。
- 结构迁移只新增表、列和兼容索引，不删除、重命名或改写旧列。保留原桌面版 exe 和配套文件，必须用旧版 exe、独立数据目录验证增量迁移后的兼容性与备份恢复，不能仅用新版源码回读代替。

### 阶段 T：先交付一条最薄闭环

1. 创建一个本地账号，保存人工业务资料和已确认策略；平台身份暂未确认时按身份契约处理。
2. 选择本地 MP4/WebM，粘贴人工逐字稿，明确本次发送范围。暂不要求在线采集、ASR、作品表现或趋势诊断。
3. 复用现有视频 Agent，一次生成分析、真人分镜和 AI 提示词；保留事实引用与采样时间。只增加薄链必需的输入、版本、素材关联和阶段状态。
4. 保存原始输入、规则版本、生成结果及人工修改；先实现可靠保存和重开，再扩完整逐镜结构编辑、深层诊断和多接口调度。
5. 实测保存 → 正常退出 → 重启 → 打开同一任务 → 查看输入/成果/版本 → 导出。用专门测试副本演练一个失败后补资料继续的案例。

验收：真实本地素材能走完上述流程，依据可查、成果可恢复，无自有指标也能完成创作。离线替身仅验证状态与保存机制；真实模型质量需另获模型预算后实际验收，不用替身冒充。T 成功后再逐项加深 B/C/D。

### 增强 B：加深账号分析与 Agent 上下文

自有账号输入：已确认策略、实际发布记录、所选指标快照、统计时间范围与口径、资源和拍摄能力。P0 自有指标只使用人工录入或 CSV 导入，不依赖平台接口。每份数据保留来源类型、来源说明、录入/导入日期、指标采集日期、统计范围和口径；统一标明“用户提供，未经平台核实”。缺失指标保留未知，错误日期、归属不符或重复导入按契约校验。

自有账号输出按结论类型分别设门槛：

| 结论类型 | 必要依据与门槛 | 未满足时的行为 |
|---|---|---|
| 资料完整性、定位表达是否清楚 | 具体账号资料字段及策略快照；不要求作品样本 | 只列缺失或矛盾字段，不猜测受众与定位 |
| 真实资源能否满足本次任务 | 用户资源声明、任务要求及各自版本；不要求作品样本，声明仍标为用户提供 | 指出缺少哪类资源或证明，不编造资质与能力 |
| 作品表现比较，如哪类开头更好 | 可比作品、具体指标快照、每组样本下限、有效指标覆盖率及统计口径 | 对该类结论只输出固定格式的资料缺口，不输出优劣或效果假设 |
| 表现趋势 | 经确认的最少观察期数、各期样本及指标覆盖要求，且口径可比 | 对该类结论只输出所缺时期、样本和指标，不声称增长或下降趋势 |

单条指标的确定性计算沿用已有口径与零分母检查，标明计算结果，不外推为账号整体结论或因果判断。

每条诊断结论必须有可解析的具体依据：资料类引用资料字段/策略版本，资源类引用资源声明和任务要求，表现类引用具体作品与指标快照，趋势类引用各期具体作品及快照。笼统写“根据账号数据”不通过；引用存在性、归属、日期、口径和类型均需校验。

门槛按类型写入诊断规则版本，同时随每次诊断保存实际门槛值、比较范围、样本数、有效指标覆盖和资料快照。调整规则生成新版本，旧诊断继续使用当时的门槛快照，不受当前设置改写。

门槛未配置或资料未达标只限制受影响的结论类型，不阻止具备依据的定位或资源分析。具体数字在阶段 A 根据真实资料确认，不把未经确认的数字作为统计可靠性标准。

资料缺口固定包含：结论类型、缺什么、当前有效数量、最低所需数量、还需补充数量、需要哪类资料、统计范围/口径、规则版本和状态原因。对已配置数值逐组计算差额；门槛尚未配置时数值留空，状态为“门槛待配置”，明确先确定哪项规则，不编造“至少需要多少”。

对标账号输入：优先使用人工登记的平台与账号身份、所选作品、评论或参考分析，附来源链接/说明和登记日期。阶段 A 探针验证成功后才允许选择相应接口；阶段 B 不以接口可用为前提。输出内容类型、开场与证明方式、可借鉴结构、适用条件和不可迁移事实。仅对当前可见样本作判断，不声称掌握完整账号表现。

生成前展示本次资料范围。Agent 只使用已确认策略和本次明确选择的资料；诊断可转为选题或任务输入。策略调整需要人工确认，旧任务继续保留原策略快照。

验收：账号目标或可用资源变化时，新任务的创作约束相应变化；自有指标与对标样本不会混入同一经营统计。没有作品样本时仍可依据账号资料判断定位或资源；表现/趋势门槛不满足时，相关结论为空且资料缺口字段完整。所有结论均能逐条打开具体依据。

### 增强 C：接入已验证的视频接口

1. 保留本地视频入口、人工逐字稿入口和三级接口选择。
2. 使用阶段 A 已实测通过的接口、字段和媒体样本接入，不在此阶段首次发现接口约束；需要重新验证时仍受已批准的累计预算控制。
3. P0 接通一条实测可用的视频获取路径；其他接口显示待接入。多选请求顺序执行，各自记录结果，部分失败不清空成功项，按平台与作品标识去重。
4. 下载成功后建立本地素材关联，明确媒体链接过期或素材缺失的补录方式。
5. 复用现有采样与视频分析规则，将账号目标、商品事实、拍摄条件、所选参考和逐字稿传给现有 Agent。
6. 普通逐字稿标记为未对齐；建议镜头时长与原视频证据时间分别保存。
7. TikHub Key 由后端管理；实现跨重启只填一次时使用 Windows 加密凭据存储。前端不持久保存、不回显完整 Key，错误、日志及导出脱敏。
8. 加密凭据必须在 PyInstaller 打包后的 exe 中实测：保存、退出、重启恢复，再清除凭据。明确绑定当前 Windows 用户，换电脑或 Windows 账户需重填；开发环境测试通过不能代替打包版验收。优先复用已有 Windows 凭据保护实现。

验收：一条真实采集视频和一条本地视频均可进入现有分析流程；缺少字幕时可补人工逐字稿继续。真实接口不可用时，本地路径仍可独立验收，接口状态保持待接入。

### 增强 D：完善逐镜结构、硬性校验与恢复

1. 在现有规则上补逐镜结构：镜头编号、建议时长、画面动作、口播、字幕、素材需求、依据和待补信息；页面再将其呈现为可编辑分镜。
2. AI 提示词关联镜头编号，包含主体、场景、动作、运镜、连续性和素材依赖。P0 交付提示词，视频成片生成服务另行接入。
3. 补齐与本链路直接相关的校验：未知引用、来源类型错配、模型响应类型、未经提供的个人经历、缺失镜头字段，以及诊断的分类门槛、逐条依据和资料缺口格式。表现类结论必须引用具体作品和指标；资料类结论不得误用作品样本门槛阻断。
4. 保存分析当时的输入快照、素材关联、规则版本、模型信息、成果版本、人工修改和检查结果。凭据及含敏感参数的临时地址不进入可分享导出。
5. 修改成果后标记相关检查需要重跑；新生成创建新版本。
6. 阶段状态至少区分未开始、处理中、待补资料、成功、失败、结果未确认。超时不自动重复付费调用；用户可以从失败阶段继续，已完成成果保留。
7. 模型响应先保存原文，再尝试本地有限格式修复：清除 BOM、外层代码围栏或唯一可确定的 JSON 包装；修复必须记录变更，不能改写内容、补造字段、删除错误引用或选择多个对象中的某一个。随后执行严格结构与语义检查；修复无法无歧义完成则标为“校验失败/待人工处理”，保留原文和错误位置。网络超时单列为“结果未确认”。两类情况均不自动再付费调用；手动重新生成创建新版本并重新检查预算。

验收：关闭软件再打开，可恢复同一任务、来源、成果和版本；替换素材、修改台词或切换策略后，旧结果被明确标记为基于旧输入。

## 5. 界面安排

现有工作台增加运营任务面板，关联现有账号策略、参考库、视频分析、稿件与反馈页面。

- 顶部：当前账号、目标、策略版本、任务状态。
- 阶段区：账号诊断、选题与参考、视频资料、分析与创作、审核与反馈。
- 成果区：查看依据、修改成果、检查问题、保存版本、继续下一步。
- 失败区：显示失败阶段、原因、缺失资料、补录与重试入口。

新建任务默认三项必填：当前账号、运营目标、真实业务资料；分析参考视频时增加必要素材输入。高级参数折叠，按阶段要求补充资料，不在首次进入时要求填写全部字段。

## 6. P0 验收

验收分层：先验收 T 最薄闭环，再验证 B/C/D 增强能力及十主题质量冒烟。展示已通过的具体范围，不将薄链通过等同于所有账号诊断和接口均已完成。真实作品发布、效果积累和表现类结论不作为 P0 发布前置条件。

### 硬性检查

- 每个输出都能追溯账号、策略版本和本次来源；未知引用与来源类型错配按契约拒绝或明确标记。
- 演示、人工录入、自有表现、外部参考和模型推断保持明确身份；未知指标不补零。
- 自有指标只来自人工录入/CSV，保存来源、录入/导入日期、采集日期和口径，显示未经平台核实。
- 账号诊断按结论类型检查门槛，依据具体且归属正确；未满足时只输出该类资料缺口，缺口必须写明缺项、数量差额和补充资料类型。
- 每次诊断保存规则版本和实际门槛值；规则更新后旧诊断仍能回看旧值。资料类分析在没有作品样本时仍可正常验证。
- 分镜字段完整、时间合法；建议时间与证据时间分开。
- 密钥不出现在返回结果、日志和导出中；正常重启可恢复加密配置。
- 部分接口失败、转写缺失、模型异常、重复点击和软件重开不会丢失已完成成果。
- 结构迁移前自动生成并验证一致性备份；备份失败禁止迁移。旧库副本上的迁移、失败恢复、备份回滚和历史导出均有实际验证记录。

### 内容质量

使用开工前固定的《P0测试与评审约定-v1》。十个主题均通过对应的硬性验收；至少八个主题通过人工质量评审。这是发现明显问题的质量冒烟门槛，不是质量稳定性或统计有效性的证明。用户负责最终人工评审，Agent 提供一主题一页的材料、硬性检查证据、完整输入输出和评分记录；Agent 自评不计为人工通过。主题、输入与评分表不得在看到结果后为提高通过率而变更；必要变更另起版本并重新完整评测。评分不能抵消编造事实或错误引用。

### 完整演练

先完成 T 的一条真实本地视频演练。登记、快照、复盘和分类门槛使用明确标注为演示的独立数据库进行机制验收，不写入真实经营库。实际发布后再登记真实指标并开展真实诊断，作为上线后的跟踪工作，不阻塞 P0 交付。

### 模型成本与人工评审工作量

- 最薄链一次合并生成；十个固定主题各一次合并生成，预计上限 11 次首次模型请求，不默认拆成多个模型阶段，也不默认追加评审模型或失败重跑。
- 视觉输入沿用每次最多 16 张采样帧；在真实验收前为所有模型分支设置明确输出上限。取得服务商、准确模型、文字与图片计费规则后，按输入、图片和输出上限计算预算并取得用户同意，之后才能调用；不能在价格未知时编造人民币总价。TikHub 的 1 元授权不覆盖这部分。
- 人工评审预计每主题 8–12 分钟，十主题约 80–120 分钟，另留准备与复核时间；这是工作量估算。材料按主题一页呈现输入边界、分镜、提示词、依据和评分项，并链接完整原文。先看 T 的一个案例，再安排十主题批评，避免一次压给评审人。

## 8. 执行约定

执行顺序固定为 A → T 最薄闭环 → B/C/D 按收益逐项增强。A 内接口探针并行，但失败不阻塞本地 T；B 的真实经营样本积累不阻塞 P0 发布。T 结束即交付可以保存、关闭、重开的实际演示，再安排增强工作。每阶段给出改动与验证证据。先补对应复现或契约测试，再实现最小改动，最后验证通过；不顺手重构无关模块。现有视频分析页面已增加集中任务面板，保存、历史只读、导出及失败恢复通过隔离浏览器验证；不据此声称真实模型质量或完整 P0 已验收。

用户已授权 TikHub 真实探测，累计上限人民币 1 元，无需重复询问同范围费用许可。开始前仍需可用的后台凭据、确定的请求输入和可核实的预算换算；缺少这些条件则完成离线准备并报告缺项。该预算不自动延伸到外部模型调用。每阶段不重复请求已经取得的同范围授权。

本轮探针规则：最多两个目标业务请求；同一失败请求不自动重试，累计两次网络超时或预算不足即终止。预算耗尽不自动释放不确定预留，也不根据账户余额自行加额；重开或追加由用户决定。本轮安全换算采用 7.50 人民币/美元，将后端累计标价上限设为 0.10 美元，最多对应 0.75 元；参考汇率查询为 6.688225，二者分别是预算安全系数和汇率观测值。实时核验价格查询、余额查询端点均为 0 美元。测试结束恢复关闭调用开关，保留后端预留账本；详见阶段 A 实测报告。
