最终人工评审：用户本人（已确认）。  
状态：主题与评分表在实现和生成结果前提出并记录；阶段 A 补齐固定输入快照及校验值后冻结。先用一个固定案例验证 T 最薄闭环，不等待十主题全部运行；分类门槛在 B 开发前确认。没有真实自有表现也可在隔离演示库验证机制。

## 1. 十个固定创作主题

以下为合成测试主题，不属于用户真实经营资料。实际测试输入必须使用明确标注的合成商品事实、参考和账号资料，不能将虚构输入写入正式业务库。

| 编号 | 固定主题 | 主要检查点 |
|---|---|---|
| T01 | 清洁刷：狭缝清洁的操作步骤 | 口播短句、动作可拍、效果有证据 |
| T02 | 桌面收纳盒：根据尺寸安排摆放 | 尺寸引用准确、展示条件完整 |
| T03 | 水杯：杯盖拆装与日常使用 | 操作连贯，不编造保温或密封实测 |
| T04 | 宠物梳毛梳：梳具使用与清理 | 不编造宠物反应、健康或除毛效果 |
| T05 | 厨房量勺：刻度辨认与使用 | 证明镜头明确，不把示意当实测 |
| T06 | 手机支架：角度调节和摆放 | 连续动作与素材条件可执行 |
| T07 | 烘焙模具：使用前的准备步骤 | 条件与限制完整，不许诺成品效果 |
| T08 | 门店服务：预约到店的流程说明 | 承接清楚，不编造客流或顾客评价 |
| T09 | 学习计时器：一轮计时的设置方法 | 不承诺成绩提升，方法表达清楚 |
| T10 | 本地维修服务：预约前需准备的信息 | 不编造资质、报价或服务保障 |

阶段 A 为每个编号保存：账号资料及策略版本、任务目标、真实资源限制、合成事实编号与来源、参考帧/台词与编号、允许和禁止的主张、目标时长、规则版本。账号与素材条件纳入输入，不在看到结果后调整。

其中至少一个主题增加同主题的账号条件对照：仅改变已确认的表达风格或拍摄资源，验证 Agent 对约束的响应。对照属于该主题的附加检查，不增加或替换十个主题的分母。

## 2. 硬性验收先于评分

- JSON 与逐镜结构符合约定，引用存在、归属正确、来源类别匹配。
- 不编造商品事实、个人经历、资质、效果、评价或账号表现。
- 建议拍摄时间与原视频证据时间明确区分，镜头时长及合计满足任务约束。
- 每镜包含必要的动作、口播/字幕、素材需求和依据；未知项明确列为待补，不用空泛描述替代交付。
- 分镜和提示词能独立阅读，账号约束和素材依赖可回查。
- 凭据不进入成果、日志或导出；合成输入不进入正式经营统计。

任意硬性失败，该主题不计质量通过。仍保留原始结果与失败记录。

## 3. 开工前固定的评分表

| 维度 | 满分 | 人工评审看什么 |
|---|---:|---|
| 账号与受众适配 | 20 | 符合定位、目标、表达边界与真实资源 |
| 自然口语 | 15 | 句子可直接说出口，信息清楚，无内部方法术语堆叠 |
| 开头与正文兑现 | 15 | 开头明确，正文回应承诺，不夸大 |
| 事实与证明表达 | 20 | 可追溯且讲得清楚，示意与真实证明分开 |
| 分镜可执行 | 20 | 谁拍、拍什么、怎么拍、说什么、多久和所需素材明确 |
| 承接与下一步 | 10 | 与任务目标一致，动作明确且可执行 |

拟定通过线：总分至少 80/100，且各维度不低于该维度满分的 60%；十个主题至少八个达到通过线，十个均须满足对应硬性验收。此评分表和通过线随本协议在阶段 A 冻结，生成结果后不追改标准。

评审记录保存每项分数、具体问题、评审人和日期。Agent 可以提供辅助说明，但最终分数及通过结论由用户确认。

十主题八个通过属于质量冒烟门槛，不能证明统计可靠性或持续质量稳定。后续根据真实使用记录扩充样本，另行报告样本范围与失败类型。每主题提供一页评审材料并附完整输入输出链接，预计每主题 8–12 分钟，十主题约 80–120 分钟，准备与复核另计。

真实模型调用预算独立审批：最薄链一次合并生成，十主题各一次，预计最多 11 次首次请求；先核实模型、图片及文本单价并设置输出上限，再给出金额上限，未经同意不调用。付费失败不自动重跑。

## 4. 独立的账号诊断门槛回归

以下为额外硬性案例，不用它们替换较难的创作主题，也不计入八成通过率的主题分母：

1. 没有作品，但定位资料完整：允许输出有具体字段引用的资料类结论。
2. 没有作品，但资源与任务要求完整：允许输出有声明/要求引用的资源匹配结论，声明保持未经核实身份。
3. 表现比较门槛未配置：表现结论为空，只返回“门槛待配置”和具体待配置项。
4. 样本低于已配置门槛：逐组返回当前量、最低量、差额、所需作品或指标及时间范围，不输出优劣判断。
5. 数量够但指标缺失、口径不一致或作品不属于本账号：相关结论不能通过。
6. 引用了未知作品、错误快照或对标账号指标：拒绝该结论，不能删掉错误引用后视为已验证。
7. 趋势观察期不足：返回需补哪些时期和每期哪些资料，不声称增长、下降或因果。
8. 门槛规则更新：新诊断使用新版本，旧诊断仍能回看当时的门槛值和输入快照。
9. 资料门槛与表现门槛互不误伤：表现不足时，具备资料依据的定位分析仍可继续。
10. 资料缺口格式检查：缺项、当前量、最低量、差额、资料类型、口径、规则版本、原因均符合契约；未配置的数值用空值，不伪造数字。

规则确认时填写每种表现/趋势结论所需的样本总量、分组下限、观察期数、指标覆盖与可比口径。这些数值当前待阶段 A 根据真实资料确定，不将临时示例作为正式阈值。

## 5. 备份与恢复回归

覆盖备份成功、备份失败禁止迁移、包含 WAL 已提交数据、迁移中断、恢复备份、旧版本回读与导出、保留失败后的数据库。全部在独立副本演练后，才允许迁移用户库。

迁移仅新增兼容结构，不修改或删除旧列。回滚必须使用保留的旧版 exe 及配套文件验证。凭据恢复需用新打包 exe 在独立测试目录做保存、退出和重启验证，并说明绑定当前 Windows 用户，换电脑或换用户需重填。

## 6. 最薄闭环及解析失败回归

T 使用一个账号、人工业务资料、本地视频和人工逐字稿，从现有 Agent 生成走到保存、退出、重启与导出；不要求真实表现比较或趋势结论，也不等待实际发布。资料不足时对受影响的结论类型按规则列缺口。

原始模型输出始终保留；本地只做可记录、无歧义的格式修复，随后严格校验。修复失败、未知引用和缺失字段进入校验失败状态，不自动发起第二次付费请求。网络超时与已收到但无法解析的结果分开记录；用户手动重新生成另建版本。

## 7. 冻结与评审纪律

阶段 A 提出本协议；T 实现前确认并冻结测试输入、现有规则基线和评分表，B 开发前单独确认分类阈值。保存版本与校验值，记录冻结日期。必要修订创建新版本，说明变更原因并重新完整评测，旧结果保留。原 v1.0 保留在计划历史目录。
