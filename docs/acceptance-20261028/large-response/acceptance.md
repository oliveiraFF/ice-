# 大响应收录与页面预览分离

用户确认采用“完整响应收录、页面限制预览、独立总量上限”方案。独立分支 `fix/large-response-collection`，基于main `3929dce`。本轮无真实供应商业务请求或新增费用。

## 修复

- 原代码在30万字符处截断JSON，然后因truncated直接拒绝收录。现在完整响应在后端脱敏后交给本次收录回调；页面和SQLite仅保留原来的30万字符预览，不返回或持久化完整供应商JSON。
- 网络读取最多10MiB+1字节，超过10MiB立即关闭响应并停止，不解析部分JSON、不重试。恰好10MiB合法JSON可接受，UTF-8多字节按字节计算。
- Catalog对传入JSON也核验10MiB紧凑UTF-8序列化长度，防止绕过网络读取的内部适配器提供超大对象。无新增第三方依赖。
- 收录与视频直链解析两入口都使用完整响应，不再从预览反向json.loads。显示截断仅影响预览，收录结果单独明确提示。
- 超限/失败仍保留原预算预留与uncertain结果，不释放预算，不自动重试。供应商成功、本机解析失败时保留成功回执并说明解析未完成；不把本机处理失败当成免费请求。
- 完整输入在本次内存中处理；不新增完整原文归档或无费用重放功能。此前已被旧版本截断的原文无法恢复，本轮不重复抓取。
