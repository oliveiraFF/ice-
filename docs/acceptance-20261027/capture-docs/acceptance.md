# 抓取窗口按官方文档对齐

用户在404修复进行中明确要求按 `https://docs.tikhub.io/` 修补抓取窗口。独立分支 `fix/capture-docs-alignment`，基于已合入404防护的main `53f413d`。不新增供应商业务请求，不改账本，不接管用户运行中的安装目录。

## 核对范围与来源

仅修补本轮涉及的现有6个抖音接口，不声称已审核全部目录：

- [视频搜索V1](https://docs.tikhub.io/370212779e0)、[视频搜索V2](https://docs.tikhub.io/370212780e0)：POST，关键词由用户填；分页初始为cursor=0、search_id为空。排序、时间、时长和内容类型按文档列出的值提供选项，保留字符串类型。文档V2页面直开曾超时，搜索抓取及现有官方OpenAPI元数据交叉核对，不推断新接口路径。
- [话题搜索V1](https://docs.tikhub.io/370212793e0)、[话题搜索V2](https://docs.tikhub.io/370212794e0)：POST，返回话题，不能按视频收录。示例请求包含空backtrace；分页参数放入高级区域。
- [App V3分享链接](https://docs.tikhub.io/186826220e0)、[Web分享链接](https://docs.tikhub.io/257556744e0)：GET，需要用户填写share_url；样例链接只显示为格式提示。官方说明可能返回空/受限作品；成功响应不代表已获得视频，不自动向另一接口重试。

保留原价格快照及调用前实时价格、额度和密钥检查；不把文档对齐当成接口真实可用认证。未测接口继续显示待验证，不自动启用、抓取、翻页或切换版本。

## 行为

- 删除6个表单的实际示例关键词/链接默认值；必填项是真实required，后端拒绝空白关键词、缺失链接和未列出的选项。
- 常用关键词、排序、时间可直接填写；更多筛选与分页折叠；高级JSON保持双向同步。数字游标为整数，排序与筛选值保持文档要求的字符串，首次空ID不被删除。
- 用途说明及手动切换按钮区分视频、话题、分享链接。点击切换只读取本地表单，不发起供应商调用。
- 当前话题接口隐藏视频收录选项；直接POST要求话题收录也在供应商请求前拒绝。原404指定路由继续拒绝，不被新表单绕过。
- 完整费用说明折叠但保留；默认仍显示一次请求、不自动重试、失败可能计费。修补同弹窗标题的主题对比度及窄屏排布。
